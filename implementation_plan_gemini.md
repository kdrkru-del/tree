# План изменений (Implementation Plan) для «Зеленый Срез»

## 1. P0 перед запуском рекламы
Эти изменения критичны для функционирования и легальности рекламы. Без них запуск Яндекс Директа запрещен.

1. **Настройка Яндекс Метрики**
   - **Доказательство:** Переменная `metrikaId` пуста. Без нее нельзя отслеживать конверсии.
   - **Действие:** Получить ID Метрики от владельца, внести в `src/data.mjs`.

2. **Заполнение юридических реквизитов**
   - **Доказательство:** В `src/data.mjs` используются заглушки `[ИНН]`, `[ОГРН]`.
   - **Действие:** Запросить реальные данные, обновить `data.mjs`. Яндекс блокирует рекламу без реквизитов.

3. **Настройка отправки лидов (Cloudflare Worker / Endpoint)**
   - **Доказательство:** Переменная `leadEndpoint` пуста. Форма не отправит данные на сервер.
   - **Действие:** Настроить Worker (из `worker/lead-worker.mjs`), развернуть, получить URL и прописать в `data.mjs`.

## 2. P1 после подтверждения владельцем
Изменения, значительно улучшающие конверсию, но требующие материалов.

1. **Замена фото-заглушек на реальное портфолио**
   - **Доказательство:** Сейчас используются стоковые фото Wikimedia (`src/data.mjs`). Конкуренты используют реальные кейсы.
   - **Действие:** Получить от владельца 10-15 реальных фотографий работ, загрузить, обновить ключи в `mediaFiles` в `data.mjs`.

2. **Актуализация цен и пакетов**
   - **Действие:** Подтвердить с владельцем прайс-лист в `priceRows` (`data.mjs:286`), чтобы цены на сайте совпадали со сметами.

## 3. P2-гипотезы после накопления данных
1. **Калькулятор стоимости расчистки (по соткам)**
   - Если трафик по расчистке будет давать много нецелевых лидов, добавить шаговый квиз вместо простой формы.
2. **Отдельные лендинги для СНТ/УК**
   - Проверить конверсию страницы `/uslugi-dlya-organizaciy/`. При необходимости расширить коммерческим предложением (PDF-презентация).

## 4. Что не делать
- **Массовая генерация региональных страниц.** Пока не подтвердится объем трафика и наличие уникального контента (фото работ именно из этих городов), не создавать 100+ SEO страниц городов, чтобы избежать пессимизации за дубли (сейчас есть базовый список в `data.mjs:266`).
- **Скрытие страницы `/prices/`.** Страница должна остаться как единый источник актуальных цен.

## 5. Зависимости и необходимые доступы
От владельца требуются следующие данные:
- ID Яндекс Метрики (и точные названия настроенных целей).
- Токен Telegram-бота и Chat ID (добавить как секреты окружения при деплое Worker).
- Реальные фотографии "До/После".
- ИНН, ОГРН, Юридическое название, телефон, Email.
- Подтвержденные цены для `priceRows`.

*Примечание: Секреты (токены) передавать только через переменные окружения, не публиковать в коде.*

## 6. Детальные карточки изменений

### Карточка 1: Интеграция Аналитики
- **Приоритет:** P0
- **Проблема:** Нет трекинга заявок.
- **Файл:** `src/data.mjs`
- **Изменение:** Заменить `metrikaId: ''` на `metrikaId: 'XXXXXXXX'`.
- **Критерий приемки:** В коде страницы рендерится скрипт Метрики с правильным ID, цели срабатывают.

## 7. Критерии приёмки
- Форма успешно отправляет POST-запрос на Endpoint и возвращает 200 OK.
- Нажатие на "Отправить" триггерит цель Метрики (reachGoal).
- Сайт открывается без стоковых фото, доверие визуально подтверждено.

## 8. План тестирования
- **Ручное:** Отправить тестовую заявку со всех форм (мобайл, десктоп). Проверить получение в Telegram.
- **Автоматическое:** Убедиться, что `scripts/check.mjs` проходит без ошибок. Проверить Lighthouse (доступность 90+).

## 9. Порядок безопасного внедрения
1. Обновление `data.mjs` (контент, реквизиты).
2. Настройка и деплой Worker (секреты).
3. Интеграция Endpoint и Метрики в `data.mjs`.
4. Тестирование на staging/локально.
5. Релиз в `main`, сборка в `gh-pages`.

## 10. План отката
При сбоях в отправке заявок:
1. Закомментировать `leadEndpoint` (откат к резервному сценарию мессенджеров).
2. Откатить коммит с обновленным `data.mjs` до предыдущей стабильной версии (`git revert <hash>`).
